# Feature 2.10 — Consent Settings API Documentation

> **Portal**: Owner  
> **Base Path**: `/api/v1`  
> **Auth**: `Authorization: Bearer <JWT_TOKEN>`  
> **Feature**: Owner Default Link Settings & Per-Link Consent Modification (Ticket 2.10)

---

## Overview

Feature 2.10 provides Credential Owners with global control over default verification link parameters (max access count, expiration time, and allowed verifier organizations). When a new verification code is created, omitted parameters automatically resolve to the owner's saved defaults. Additionally, owners can update consent settings on already created active links.

---

## 1. Owner Portal Endpoints

### 1.1 Get Default Link Settings

> **`GET /api/v1/owner/link-settings`**  
> **Summary**: `[Owner] Get Default Link Settings`  
> **Auth**: Owner JWT (`Authorization: Bearer {{owner_access_token}}`)

Retrieves the authenticated owner's saved default consent settings. If the owner has never configured settings, all value fields return `null` / empty list.

#### Response `200 OK`
```json
{
  "success": true,
  "data": {
    "default_consent_mode": "access_count",
    "default_max_access_count": 5,
    "default_expiry_hours": null,
    "default_allowed_org_ids": []
  },
  "message": "Default link settings retrieved.",
  "error_code": null
}
```

| Field | Type | Description |
|---|---|---|
| `default_consent_mode` | String / Null | Derived mode: `"access_count"`, `"time_bound"`, `"trusted_orgs"`, `"custom"`, or `null` |
| `default_max_access_count` | Integer / Null | Default maximum access count (`>= 1`), or `null` |
| `default_expiry_hours` | Integer / Null | Default link lifespan in hours (`>= 1`), or `null` |
| `default_allowed_org_ids` | Array[String] | Default allowed verifier organization ObjectIds |

#### Error Responses
- `401 UNAUTHORIZED` — Missing or invalid Bearer JWT

### 1.2 Update Default Link Settings

> **`PATCH /api/v1/owner/link-settings`**  
> **Summary**: `[Owner] Update Default Link Settings`  
> **Auth**: Owner JWT (`Authorization: Bearer {{owner_access_token}}`)

Partially updates the owner's global default consent settings. Only fields explicitly included in the request body are updated.

#### Request Body
```json
{
  "default_consent_mode": "custom",
  "default_max_access_count": 10,
  "default_expiry_hours": 48
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `default_consent_mode` | String | No | Mode target: `"access_count"`, `"time_bound"`, `"trusted_orgs"`, `"custom"`, or `null` |
| `default_max_access_count` | Integer | No | Default max access count (`>= 1`), or `null` to reset |
| `default_expiry_hours` | Integer | No | Default lifespan in hours (`>= 1`), or `null` to reset |
| `default_allowed_org_ids` | Array[String] | No | Allowed verifier org IDs, or `null`/`[]` to reset |

#### Response `200 OK`
```json
{
  "success": true,
  "data": {
    "default_consent_mode": "custom",
    "default_max_access_count": 10,
    "default_expiry_hours": 48,
    "default_allowed_org_ids": []
  },
  "message": "Default link settings updated.",
  "error_code": null
}
```

#### Error Responses
- `422 INVALID_DEFAULT_SETTINGS` — When `default_consent_mode` is `"custom"`, fewer than 2 value dimensions are set in the merged result
- `422 UNPROCESSABLE_ENTITY` — `default_max_access_count` < 1 or `default_expiry_hours` < 1

### 1.3 Update Verification Code Settings (Created Link)

> **`PATCH /api/v1/owner/verified-links/{link_id}`**  
> **Summary**: `[Owner] Update Verification Code Settings`  
> **Auth**: Owner JWT (`Authorization: Bearer {{owner_access_token}}`)

Modifies consent settings on an existing active verification link. Recalculates consent mode and resets `remaining_access_count` if `max_access_count` is updated.

#### Request Body
```json
{
  "expires_at": "2026-12-31T23:59:59Z",
  "max_access_count": 10
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `expires_at` | String (ISO 8601) | No | Expiration datetime (must be in the future), or `null` for Unlimited |
| `allowed_org_ids` | Array[String] | No | Allowed verifier org ObjectIds, or `[]` / `null` for Unlimited |
| `max_access_count` | Integer | No | Maximum access count (`>= 1`), or `null` for Unlimited |

#### Response `200 OK`
```json
{
  "success": true,
  "data": {
    "id": "66b9f1d2e4b0a1a2b3c4d5e7",
    "code": "A9K3X7M2P4Q8",
    "credential_id": "6a796d47930eebede514ce0d",
    "consent_mode": "custom",
    "expires_at": "2026-12-31T23:59:59Z",
    "allowed_org_ids": [],
    "max_access_count": 10,
    "remaining_access_count": 10,
    "display_status": "active",
    "created_at": "2026-08-10T04:15:00Z",
    "revoked_at": null
  },
  "message": "Verification code settings updated successfully.",
  "error_code": null
}
```

#### Error Responses
- `404 VERIFIED_LINK_NOT_FOUND` — Link ID not found or not owned by requester
- `409 LINK_ALREADY_REVOKED` — Attempted to edit a link that is already revoked
- `400 INVALID_EXPIRATION` — `expires_at` is in the past
- `400 INVALID_ACCESS_COUNT` — `max_access_count` < 1
- `400 INVALID_ORG_ID` — Invalid or non-existent organization ID provided

---

## 2. Denial / Failure Scenarios Table

| Scenario / Trigger | `error_code` | `message` |
|---|---|---|
| Custom mode saved with < 2 dimensions | `INVALID_DEFAULT_SETTINGS` | Custom mode requires at least two of: max access count, expiry hours, allowed organizations. |
| Link ID not found / wrong owner | `VERIFIED_LINK_NOT_FOUND` | Verified link not found. |
| Editing a revoked link | `LINK_ALREADY_REVOKED` | Verified link has already been revoked. |
| Past expiration date | `INVALID_EXPIRATION` | Expiration date must be in the future. |
| Invalid max access count | `INVALID_ACCESS_COUNT` | Max access count must be at least 1. |
| Non-existent verifier org ID | `INVALID_ORG_ID` | One or more organization IDs are invalid. |
